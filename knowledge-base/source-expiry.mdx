---
title: "Manage Expired Knowledge Sources"
description: "Review expired content and approve it again with a new validity date."
---

Knowledge-source expiry helps keep time-limited policies, offers, and procedures out of the active knowledge used by agents. Expired items remain available for review in the **Expired** tab so an administrator can inspect old material without treating it as current guidance.

## Review expired sources

Open **Knowledge Base** and select **Expired**. Search or filter the list, then open a source to inspect its content and details. The list includes the expiry date so you can distinguish old material from a source that needs renewal.

## Approve a source again

1. Select one or more expired sources and choose **Approve**.
2. Choose the knowledge bases that should receive the approved content when applicable.
3. Set a future expiry date if the renewed content has a validity period.
4. Confirm approval.

When approving one item, the dialog starts with its existing expiry date. Replace an old date with a future date before confirming. Bulk approval starts without a preselected expiry date because the selected items may have different dates.

Approve only after checking the content itself. Extending a date does not update a rate, promotion, or policy embedded in the document. If the source should no longer be used, reject it instead of renewing it.

## Use dates in answers

Keep effective dates and version references in the source text when callers need them. Expiry controls source availability; it does not invent an effective date for a response. For a live balance or transaction status, use an [API tool](/voice-agents/custom-api-tools) to retrieve the current value.

See [Adding Web Pages and Documents](/knowledge-base/adding-web-pages-and-documents) for ingestion and approval, and [Knowledge Base Settings](/knowledge-base/knowledge-base-settings) for retrieval configuration.
