The **Evaluation** tab on a Voice Agent attaches your team's **scorecards** to that agent. Every call the agent completes is then scored automatically against each attached scorecard — no one has to sit down and listen to calls to know whether the agent is doing its job.

This is separate from the **General** / **Model Settings** / **Advanced Settings** tabs covered in [Voice Agent Settings](/voice-agents/voice-agent-settings). It isn't a call-behavior setting — scoring runs _after_ the call, against the finished transcript and tool logs.

<Note>
  Don't confuse this with the **Human Feedback** widget you'll see on an individual call in Call History, which lets a reviewer manually mark that one call as failed and pick an error category. That's a person making an ad-hoc judgment call about a single call. Scorecards are the opposite: an automatic grading system that scores every call the same way, without a human involved.
</Note>

## How it works

1. **Build a scorecard.** Scorecards belong to your team, not to one agent, and are created under **AI Agent Testing \> Scorecards**. A scorecard picks what to evaluate, a judge model, and a set of evaluation criteria worth up to 100 points in total. See [Scorecards](/evaluations/scorecards).
2. **Attach it to the agent.** Open the Voice Agent's **Evaluation** tab, click **Start Editing**, and attach one or more scorecards. Search the list to find one; use the detach action to remove one ("This voice agent will no longer be evaluated against this scorecard.").
3. **Publish.** Scorecard attachments are part of the agent's draft, like any other setting. See [Voice Agent Versioning](/voice-agents/voice-agent-versioning).
4. **A call finishes, evaluation runs, results land in Call History.** No manual step — every completed call is scored against each attached scorecard.

The Evaluation tab lists each attached scorecard with:

| Column | What it shows |
| --- | --- |
| **Name** | The scorecard. Click it to open the scorecard. |
| **Scoring** | **Contributes to result**, or **Informational** if the scorecard is shown but doesn't decide pass/fail. |
| **Pass threshold** | The minimum passing score, as a percentage. |
| **Knockouts** | How many knockout criteria the scorecard has (see below). |
| **Metrics** | How many evaluation criteria the scorecard has. |

Because scorecards are shared, you can reuse the same scorecard across many Voice Agents, and changing a scorecard changes how every agent it's attached to is graded.

## What a scorecard evaluates

Each scorecard has one **evaluation target** — the side of the call it grades:

| Target | What it scores |
| --- | --- |
| **Agent** | How the AI agent handled the call. |
| **Caller** | The caller's side of the conversation. |
| **Human agent** | The person who takes over after a transfer. Calls without a transfer are skipped. |

To grade more than one side, attach one scorecard per target.

## Evaluation criteria

A scorecard is built from evaluation criteria from your team's library (**AI Agent Testing \> Evaluation Criteria**). Each criterion is either a **deterministic check** — a fact verified mechanically from the call, such as whether a tool was called or whether the agent said a phrase — or an **LLM-judged** criterion, a grading prompt the scorecard's judge model applies to the transcript. See [Evaluation Criteria](/evaluations/evaluation-metrics) for every criterion type.

Deterministic checks are pass/fail facts, so they need no LLM call and are cheap and instant. Use LLM-judged criteria for anything that requires judgment: tone, adherence to a policy, whether the agent handled an objection well.

## Scoring: the 100-point model

Each scorecard scores a call out of **100 points**:

- You allocate **Maximum points** to each criterion, and the criteria must total exactly 100. **Split evenly** and **Scale proportionally** help you balance them.
- Each criterion's scoring rule decides how many of its points the call earns — for example, all points for a passed check, points per rating level for a rating, points per completed requirement for a checklist, or deductions for each occurrence of a violation (**All or nothing** or **Graduated deductions**).
- Each criterion has a **behavior** on the scorecard:
  - **Standard** — counts normally toward the 100-point total and pass/fail.
  - **Knockout** — counts normally, but failing it sets the whole call's final score to 0.
  - **Informational only** — evaluated and shown, but never counted toward the score.
- The call passes when its total points meet the scorecard's **Minimum passing score**.

Knockouts are how you enforce a hard rule: no matter how well the rest of the call went, failing a knockout fails the call.

## Where results show up

**Call History** shows each call's evaluation result, and you can filter calls by result (**Passed**, **Failed**, **Not evaluated**) and score range.

Open a call's detail view for the full breakdown under **Evaluation**: each scorecard's score, its pass threshold, and the result of every criterion in a **Metric Breakdown**. If a knockout failed, the result says "Critical metric failed — final score set to 0." and names the criterion. From the same section, **Create test case** turns the call into a test case for [Test Suites](/evaluations/creating-an-evaluator).

## An example: validating identity before discussing account details

Evaluation criteria are generic — nothing here is banking-specific — but they're the kind of building block a bank would use to enforce a hard rule mechanically instead of hoping the agent's prompt is followed. For example, an **Agent** scorecard with a **Tool Called** check, marked as a **Knockout**, verifying that the **Built-in Validate** tool (see [Voice Agent Tools](/voice-agents/voice-agent-tools)) ran before the call moved on to discuss account specifics. Because it's a deterministic check, this catches a real process violation on every single call — no LLM judgment involved — and because it's a knockout, any call that skips validation fails outright.

This is a different mechanism from [Phone Verification](/voice-agents/voice-agent-advanced-capabilities#phone-verification), which confirms a caller's identity by matching a spoken phone number against the one on file for that contact, at call time. Built-in Validate is a general-purpose tool for validating a spoken field — an account number, an ID — against a regex, and using it in a scorecard is one way to confirm the agent actually invoked it, after the fact.

<Note>
  This is one example configuration built from generic criterion types, not a claim that Revve ships a banking-specific evaluation feature. Any team can define the same kind of check for whatever field or tool call matters to their process.
</Note>

## Older agent versions

Before scorecards, each Voice Agent had its own inline evaluation policy, with separate Caller and Agent groups, weights, and a minimum score out of 5. If you view a published version from that time that has no scorecards attached, the Evaluation tab shows its legacy policy read-only, with the note "This version has no scorecards attached. Its legacy evaluation policy is shown below." New configuration always uses scorecards.

## The trap: nothing attached

A Voice Agent with no scorecards attached isn't evaluated at all — its calls show as **Not evaluated** in Call History. Attach at least one scorecard, and publish, before you rely on scores. A scorecard with a single well-chosen knockout check is more useful than none.
