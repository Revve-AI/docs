title: "Creating and Connecting Nodes"
description: "How to add new nodes, define transitions between them, and set conditions that control the conversation path."
---

A conversational flow is built from **nodes** (the stages of a conversation) and **transitions** (the rules that move the conversation from one stage to the next). This guide walks you through creating both.

## Adding a New Node

1. Make sure you are in editing mode (click **Start Editing** if the button is visible).
2. Click the **Add Node** button in the toolbar above the canvas.
3. In the **What Should This Node Do?** dialog, pick a node type (see the table below).
4. Fill in the node's details:

![The Create New Node dialog with fields for name, type, and instructions](/screenshots/flow-create-node-dialog.png)

| Field | Description |
|-------|-------------|
| **Node Name** | A short, descriptive label for this stage of the conversation (for example, "Greeting", "Qualify Lead", "Schedule Demo"). This name appears on the node card in the canvas. |
| **Instructions** | What the AI should say and do at this step. Write in plain language what the agent should do, say, or ask when the conversation reaches this node. Not shown for Logic Split, Extract Variables, or Code nodes, which never speak. |

Click **Change Type** to go back and pick a different type.

5. Click **Create Node**. The new node appears on the canvas and you can drag it to the desired position.

### Node Types

| Type | Purpose |
|------|---------|
| **Normal Conversation** | A general-purpose node for dialogue, Q&A, or any step that does not require built-in contact or scheduling features. |
| **Contact Collection** | Automatically enables contact-information gathering at this node. The agent will prompt the visitor for details such as name, email, and phone number. |
| **Schedule Meeting** | Automatically enables meeting-booking capabilities at this node. The agent can check calendar availability and help the visitor pick a time. |
| **Logic Split** | Routes the conversation instantly based on rules or the conversation. Never sends a message. |
| **Extract Variables** | Silently captures details from the conversation (like a department or order number) into variables you can use in later nodes. |
| **Code** | Runs JavaScript in a sandbox to call APIs, compute values, or set variables. Never sends a message. |

Logic Split, Extract Variables, and Code nodes always have an **Else** transition ("When nothing else matches"), which can't be deleted and is used when no other condition matches.

<Note>
Chat flows don't offer the **Transfer Call** node, which hands off phone calls. To hand a chat conversation to a human, use the **Human Escalation** toggle instead ([Flow Node Features](/conversational-flow/flow-node-features)).
</Note>

## Understanding Transitions

Transitions are the arrows that connect one node to another. Each transition carries a **condition** that tells the agent when to move the conversation along that path.

For example, a "Greeting" node might have two transitions:
- "If the visitor is a new prospect asking about pricing" -- leads to the "New Prospect Information" node.
- "If the visitor is an existing customer" -- leads to the "Existing Customer Support" node.

The AI reads all available transition conditions at each turn and picks the one that best matches the visitor's latest message. If none match, the conversation stays at the current node.

## Creating a Transition

There are two ways to add a transition:

### Option A -- From the Node Panel

Click a node to open its panel on the right. The **Transitions** section lists the node's transitions. In editing mode, click **Add transition** to open the **Create New Transition** dialog.

### Option B -- Drag a Connection

1. Hover over a node until you see a small **handle** (a dot) at the edge of the node.
2. Click and drag from that handle to another node on the canvas.
3. Release the mouse over the target node. A new transition is created. Open it to set its condition.

## Editing a Transition

Click a transition in the node panel's **Transitions** section, or the pencil button on a transition arrow in the canvas, to open the **Edit Transition** dialog. Clicking the arrow itself only highlights it.

![The Edit Transition dialog showing name, condition, destination, and automation fields](/screenshots/flow-edit-transition-panel.png)

| Field | Description |
|-------|-------------|
| **Name** | Optional. A short label for your own reference. This name does not affect AI behavior. Maximum 100 characters. |
| **Condition** | When to follow this transition. Choose a mode:<br/>**AI decides** — a plain-language rule the AI judges, written as a clear "if" statement describing the visitor's intent or message content.<br/>**Rule** — a deterministic check built from a **Variable**, a **Check**, and a **Value**. Combine several with **Match: All** or **Any**. Rules are evaluated before AI-judged conditions. |
| **Destination** | The node this transition leads to. |
| **Automation** | Optional. Lets you set custom contact fields automatically when this transition is triggered. |

To reorder transitions, drag them in the node panel. To delete one, click its delete button in the **Transitions** section and confirm.

## Rearranging Nodes

Drag any node to reposition it on the canvas. The transition arrows automatically adjust to follow the new layout. Positions are saved to your draft automatically. Use **Auto arrange** in the toolbar to lay out the whole flow.

## Deleting a Node

1. Click on the node to open its configuration panel on the right.
2. Open the **Node options** menu (**⋯**) at the top of the panel and click **Delete Node**.
3. Confirm the deletion when prompted.

The same menu has **Duplicate Node** to copy a node.

Deleting a node also removes all transitions that lead to or from it. Make sure you reassign any critical paths before deleting.

## Best Practices

- **Keep conditions specific and non-overlapping.** If two transitions from the same node have vague or similar conditions, the AI may choose the wrong path. Use clear, distinct criteria for each transition.
- **Always have a fallback path.** Consider adding a transition for cases where the visitor's intent does not match any specific condition (for example, "If the visitor's request does not match any other category").
- **Name your nodes descriptively.** Short, clear names like "Qualify Lead" or "Book Demo" make the flow easy to read at a glance.
- **Use Rules for exact checks.** When a transition depends on a known value — a counter, a captured field — use a **Rule** condition instead of asking the AI to judge it.
- **Test after major changes.** Use the **Preview** tab (website and SMS agents) to walk through your flow as a visitor would, verifying that each transition fires at the right time.
