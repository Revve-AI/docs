A **Scorecard** (**AI Agent Testing → Scorecards** in the left dashboard nav, visible with the **Manage Agents** permission) is a reusable grading rubric. It picks whose side of the call to evaluate, the model that judges it, and a set of criteria from your [Evaluation Criteria](/evaluations/evaluation-metrics) library worth up to **100 points** in total, with a minimum passing score. Every conversation graded by the scorecard is scored the same way, so "did this call pass?" means the same thing across test runs, live calls, and audits.

## Where scorecards are used

| Where | What it grades | When |
|-------|----------------|------|
| [Test Suites](/evaluations/creating-an-evaluator) | Simulated test conversations. Attach scorecards to a suite (shared by all its test cases) or to one test case. | When you run a suite — pre-ship regression testing. |
| Voice Agent [Evaluation tab](/voice-agents/voice-agent-evaluation) | Every live call one voice agent completes. | Automatically, after each call. |
| [Uploaded call recordings](#scoring-uploaded-recordings) | Batches of recordings uploaded in Call History. | When you upload a batch — QA sampling, compliance audits, calls made outside Revve. |
| Manual call analysis | Calls your team members place themselves. | After each call. |

Because a scorecard only references criteria from the shared library, editing a criterion changes how every scorecard that uses it grades. The scorecard owns the points, behavior, and passing score.

## The Scorecards page

The page lists your team's scorecards:

| Column | Meaning |
|--------|---------|
| **Name** | The scorecard's name. Click the row to open it for editing. |
| **Criteria** | How many criteria the scorecard includes. |
| **Updated** | When it was last changed. |

Use **New scorecard** to create one, or **Import** to create scorecards and their criteria from a CSV — each row is one criterion in a scorecard, with its type set to `deterministic` or `llm_judge`.

## Creating and editing a scorecard

Click **New scorecard** to open the scorecard editor. Clicking an existing row opens the same page for editing. It has four sections:

**Basic details**

| Field | Notes |
|-------|-------|
| **Name** | Required, e.g. "Compliance scorecard". Name it after the *question it answers* (Compliance, Greeting quality, Collections script adherence), not after one batch or agent — the point is reuse. |
| **Description** | What the scorecard measures. It's what tells a teammate whether to reuse your scorecard or create another. |

**Evaluation target** — *What do you want to evaluate?*

| Target | What it scores |
|--------|----------------|
| **Agent** | How the AI agent handled the call. |
| **Caller** | The caller's side of the conversation. |
| **Human agent** | The person who takes over after a transfer. Calls without a transfer are skipped. |

Only criteria for the chosen target can be added. To grade more than one side, create one scorecard per target.

**Judge model** — the model used to evaluate the LLM-judged criteria. Deterministic checks don't use it.

**Evaluation criteria** — click **Add criterion** and search your library. For each criterion, set:

- **Points** — the criterion's **Maximum points**. All criteria must add up to exactly **100**. **Split evenly** and **Scale proportionally** help balance them, and a running total warns you when you're over or under.
- **Scoring rule** — how the criterion earns its points. The options depend on the criterion's scoring:
  - Pass/fail checks earn all their points or none.
  - **Scale 1-5** criteria award points per rating (**Rating awards**).
  - **Checklist** criteria use **Completion tiers** (every requirement equal) or **Points per requirement** (important requirements worth more).
  - **Count occurrences** criteria deduct points: **All or nothing** (any violation loses all points) or **Graduated deductions** (deduct more as occurrences increase).
- **Behavior** on this scorecard:
  - **Standard** — counts normally toward the 100-point total and pass/fail.
  - **Knockout** — counts normally, but failing it sets the whole call's final score to 0.
  - **Informational only** — evaluated and shown, but never counted toward the score.

Finally, set the **Minimum passing score**: a call passes when its total points meet this value.

Submit with **Create scorecard** (new) or **Save changes** (editing).

<Tip>
Allocate points by what a failure costs you, not by how easy the criterion is to check. In a compliance scorecard, make "read the required disclosure" a **Knockout** so it fails the call on its own, and let style criteria like tone share the remaining points.
</Tip>

## Scoring uploaded recordings

To grade calls that already happened — a QA sample, recordings from a legacy dialer, or calls made outside Revve — upload them in **Call History**:

1. Click **Upload batch** to open **Upload Audio Batch**.
2. Choose the **Scorecard** to grade with.
3. Choose the **Agent** who handled the calls, or add a **Manifest** that sets the agent, time, and direction per call.
4. Optionally name the batch, then add the **Audio files**.

Scoring is asynchronous. Uploaded calls appear in Call History — filter **Source** by **Upload** to find them — and each scored call shows its scorecard result in its **Evaluation** section.

| Situation | Why a scorecard |
|-----------|-----------------|
| Compliance audit of a sample of last month's collections calls | One rubric applied identically to every sampled recording — auditable, repeatable month over month. |
| Scoring recordings from a legacy dialer before migrating to Revve | The calls never touched a Revve agent; grade them with the same scorecard your Revve agents use, for a like-for-like baseline. |
| Spot-checking quality with a weighted rubric | Cheaper than grading every call — sample, upload, score, and repeat with the same scorecard so trends are comparable. |
