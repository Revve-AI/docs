**Evaluation Criteria** (**AI Agent Testing → Evaluation Criteria** in the left dashboard nav) is the library where your team defines reusable standards for reviewing agent conversations. You define a criterion once, then add it to as many [scorecards](/evaluations/scorecards) as you like. Scorecards grade conversations wherever they're used — Test Suites, a Voice Agent's **Evaluation** tab, and manual call analysis.

![The Evaluation Criteria library page, showing the criteria table and the New Criterion button](/screenshots/ai-agent-testing-nav.png)

<Note>
A criterion defines **what** the judge checks and **how** it reports the result. The scorecard decides **how many points** that result is worth, whether failing it is a knockout, and the passing score. That's why the same criterion can be worth 10 points on one scorecard and 40 on another.

Editing a criterion here changes it on every scorecard that uses it.
</Note>

## The criteria list

The table shows each criterion's **Name**, **Type**, **Scoring**, **Description**, and **Created** date. Search by name, or filter by type: **All types**, **Deterministic**, or **LLM Judge**.

<Tip>
Check for near-duplicates before creating a new criterion — it's easy to end up with two similarly named LLM Judge criteria asking almost the same question, which doubles judge cost without adding signal.
</Tip>

## Creating a criterion

Click **New Criterion** to open the **New evaluation criterion** panel. Click an existing criterion's row to open the same panel as **Edit evaluation criterion**.

| Field | Notes |
|-------|-------|
| **Name** | Required, e.g. "Verified Identity". Keep it specific enough to recognize in a scorecard's criteria table, where you won't see the full description. |
| **Description** | Optional — what this criterion checks. Worth filling in; it's the context a teammate sees before adding your criterion to their scorecard. |
| **Type** | Required. **Deterministic** or **LLM Judge**. |

Submit with **Create** for a new criterion, or **Save Changes** when editing.

### Deterministic criteria

A deterministic criterion is a fact checked mechanically against the conversation — pass or fail, no LLM involved, so it's cheap and instant. Choose a **Check Type**:

| Check | What it verifies | Settings |
|-------|------------------|----------|
| **Tool Called** | A tool appears in the tool call logs. | **Tool Name** |
| **Tool Not Called** | A tool does not appear in the logs. | **Tool Name** |
| **Tool Called With** | A tool was called with matching parameters. | **Tool Name**, **Expected Parameters (JSON)** |
| **Contains Text** | An agent message contains a substring. | **Text** |
| **Not Contains Text** | The agent never says a substring. | **Text** |
| **Regex Match** | An agent message matches a regex pattern. | **Pattern** |
| **Turn Count** | The conversation completed within N turns. | **Max Turns** |

Use deterministic checks for facts you can verify from logs — whether a validation tool ran, whether a required phrase was said.

### LLM Judge criteria

An LLM Judge criterion is a grading prompt that the scorecard's judge model applies to the transcript. Use it for anything that requires judgment: tone, adherence to a policy, whether the agent handled an objection well.

**Scoring** — how the judge reports its result:

| Scoring | What the judge does | How the scorecard uses it |
|---------|---------------------|---------------------------|
| **Binary (pass/fail)** | Returns true or false. | Assigns the points. |
| **Scale 1-5** | Assigns 1–5 using your rubric. | Maps each score to points. |
| **Checklist** | Reports which required steps happened. | Sets award tiers, or points per requirement. |
| **Count occurrences** | Counts how many times one event happened. | Decides how the count affects points, e.g. a deduction per occurrence. |

**Judge prompt** — the grading instruction. Write it as a specific question, e.g. "Did the agent verify the customer's identity before providing account information?", not a vague theme like "was the agent helpful". For **Count occurrences**, this field becomes **What should the judge count?** — describe one event, e.g. "Count each time the agent interrupts the caller before they finish speaking."

**Who is being evaluated?** — whose lines drive the score. The other lines stay in the transcript as context.

| Option | Scores |
|--------|--------|
| **AI Agent** | The agent's utterances. |
| **Caller** | The caller's utterances. |
| **Human agent** | The person who takes over after a transfer. |

A criterion can only be added to a scorecard whose evaluation target matches.

**Score rubric** — shown for **Scale 1-5**. Fill in **Score 1** through **Score 5** with what in the conversation would warrant each score. Fill in every level, not just the ends — a judge with no definition for "3" will assign one anyway, just inconsistently.

**Requirements** — shown for **Checklist**. Click **Add requirement** for each step the judge should observe ("What must happen in the conversation?"). Point tiers are configured on the scorecard.

## Importing criteria

To create many criteria at once, click **Import** and upload an Excel or CSV file. Click **Download template** for the expected columns. One file can contain both types — set each row's type to `deterministic` or `llm_judge`.

## Deleting a criterion

Use the row's delete action to open **Delete evaluation criterion**. If the criterion is used by scorecards, the dialog names how many and warns that deleting it will remove it from them. Deletion can't be undone, so review those scorecards first — removing a criterion changes their point totals.
