title: "What Is AI Agent Testing?"
description: "Pre-ship regression testing for your agents — group test cases into suites, run them against a Text or Voice agent version, and see pass/fail results and transcripts before real customers hit the change."
---

**AI Agent Testing** is where you test an agent before it goes live, not after. You write test cases — a simulated caller or visitor with instructions — group them into a **Test Suite** for one agent, run the suite against an agent version, and get back a pass/fail verdict per test case with the full transcript, graded by your scorecards. It's the tool for answering "did my prompt edit break anything?" before you publish, rather than finding out from a customer complaint or a bad call.

AI Agent Testing is its own item in the left dashboard nav, visible to anyone holding the **Manage Agents** permission (see [Roles & Permissions](/governance-access/roles-and-permissions)). It expands to six pages: **Experiments**, **Scorecards**, **Evaluation Criteria**, **Test Suites**, **Test Runs**, and **Simulator Profiles**.

![The AI Agent Testing section in the left dashboard nav](/screenshots/ai-agent-testing-nav.png)

<Note>
AI Agent Testing is easy to confuse with two other things that use similar words:

1. **The per-Voice-Agent Evaluation tab** ([Voice Agent Evaluation](/voice-agents/voice-agent-evaluation)) attaches scorecards to one voice agent so every *live* call it completes is graded automatically, after the fact. Test Suites, by contrast, run simulated tests *before* a call ever happens with a real customer. Both use the same scorecards.
2. **The per-Chat-Agent "Evaluations" tab** (mentioned in [Creating Your First Chat Agent](/getting-started/creating-your-first-chat-agent)) is an older, separate legacy system for one chatbot's test cases and test history. It predates this product and isn't documented further here.
</Note>

## How it works

1. **Create a Test Suite for one agent.** A suite groups test cases and shared scorecards so you can run one consistent evaluation against any version of that agent. Pick the **Agent type** (Text or Voice) and the **Agent** when you create it — the agent can't be changed afterward.
2. **Add test cases.** Each test case describes one conversation to simulate: instructions for the simulated caller or visitor, whether it runs as **Text** or **Voice**, a **Caller profile** for voice, call variables, and limits such as max turns and max duration. Test cases run in creation order. See [Creating a Test Case](/evaluations/creating-an-evaluator).
3. **Grade with scorecards.** Attach **shared scorecards** to the suite so every test case is graded the same way, and add extra scorecards to individual test cases when needed. Scorecards are built from your team's **Evaluation Criteria** library. See [Scorecards](/evaluations/scorecards) and [Evaluation Criteria](/evaluations/evaluation-metrics).
4. **Run the suite.** Click **Run suite**, choose the **Agent version** to test (including your draft), optionally name the run, and confirm. The run is queued and executes asynchronously.
5. **Read the results.** **Test Runs** lists every run with its suite, agent version, status, results, and duration. Open a run for each test case's pass/fail result, transcript, and scorecard breakdown, and **Re-run** it after you fix something.

## The pages

| Page | What it's for | Where to go deeper |
|------|----------------|---------------------|
| **Experiments** | Run two published versions of an agent side by side on real traffic, then ship the one that does better. Experiments are created from an agent's **Experiments** tab or when publishing with **Test with an experiment first**. | [Publishing & Versioning](/getting-started/publishing-and-versioning) |
| **Scorecards** | Grading rubrics — an evaluation target, a judge model, and criteria worth 100 points — used by Test Suites, voice agents' Evaluation tab, and manual call analysis. | [Scorecards](/evaluations/scorecards) |
| **Evaluation Criteria** | The shared library of scoring criteria (deterministic checks and LLM-judged criteria) that scorecards are built from. | [Evaluation Criteria](/evaluations/evaluation-metrics) |
| **Test Suites** | Groups of test cases for one agent, with shared scorecards. Run a suite against any version of the agent. Filter the list by agent type (**Text** / **Voice**). | [Creating a Test Case](/evaluations/creating-an-evaluator) |
| **Test Runs** | History of queued and executed suite runs — status, results, transcripts. Runs are started from a suite, not from here. | [Creating a Test Case](/evaluations/creating-an-evaluator) |
| **Simulator Profiles** | Voice-only. Reusable simulated-caller configurations — LLM, TTS voice and language, STT, and a persona instruction — used as a voice test case's **Caller profile**. | [Simulator Profiles](/evaluations/evaluation-profiles) |

<Tip>
You can turn a real call into a test case: open the call in Call History and click **Create test case** in its **Evaluation** section. This is a quick way to lock in a conversation that went wrong so it's tested on every future version.
</Tip>
