By the end of this page you'll have created a Test Suite, added a test case, run it, and read the results. This assumes you already have at least one [Scorecard](/evaluations/scorecards) to grade with and, if you'll use an AI-generated caller, at least one [Simulator Profile](/evaluations/evaluation-profiles).

## Step 1: Create a Test Suite

Test cases live inside a suite, and every suite belongs to one agent. Go to **AI Agent Testing > Test Suites** and click **New suite** (or **Create first suite** if you have none yet).

| Field | What to enter |
|-------|---------------|
| **Name** | Required, e.g. "Booking regression". |
| **Description** | Optional — what this suite covers. |
| **Agent type** | **Text** or **Voice**. |
| **Agent** | The agent under test. It can't be changed after the suite is created. |

On the suite, attach **shared scorecards** — every test case in the suite is graded against them. Use the search box and the **Agent type** filter on the Test Suites list to find a suite later.

## Step 2: Add a test case

On the suite, click **New test case**. The form has four sections.

**Test case details**

- **Suite** — preselected when you start from a suite. The **Agent** is derived from the suite and can't be edited here.
- **Name** — required, e.g. "Appointment Cancellation".
- **Description** — optional, what this test case checks.

**Conversation**

- **Caller behavior** — **AI-generated caller** or **Scripted caller**.
  - **AI-generated caller**: write **Instructions** — the customer persona and scenario. The simulated caller improvises within them. You can insert variables.
  - **Scripted caller**: build the **Script** — the exact turns the simulated caller sends, in order. For voice suites you can record each line; once every line is recorded, the test uses recorded playback instead of text-to-speech.
- **Caller profile** — required for AI-generated callers. It controls how the simulated caller behaves (and, for voice, how it sounds). See [Simulator Profiles](/evaluations/evaluation-profiles).
- **Agent speaks first** — voice only. Turn on when the agent under test should open the conversation (for example, an outbound call flow).

**Scorecards**

The suite's shared scorecards are listed as **Inherited from suite**. Add more scorecards here when this test case needs extra checks. A test case needs at least one scorecard that contributes to the result, inherited or its own, before it can run.

**Limits**

- **Max turns** — how many conversation turns the simulation is allowed before it stops.
- **Max duration (seconds)** — voice only, a hard cap on call length.

Set both from what a normal conversation for this scenario looks like, padded a bit.

An **Advanced** section (collapsed by default) holds:

- **Tool mocks** — stub tool-call responses so the test runs without real integrations.
- **Call variables** — values available during the simulated conversation. Voice suites have two sets: what the **Agent under test** knows about the customer, and what the **Simulated caller** claims about themselves.
- **Tags** and **Folder path** — for organizing test cases.

Save the test case. Test cases run in the order they were created.

<Tip>
To test a real conversation, open a call in Call History and click **Create test case** in its **Evaluation** section. The form opens with the call imported ("Imported from call"); pick a voice suite for that agent and save.
</Tip>

<Tip>
To reuse a test case for another agent, open it and choose **Test this against another agent**. Pick a **Target suite** assigned to the other agent, then click **Duplicate test case**.
</Tip>

## Step 3: Run the suite

Runs always start from a suite. On the suite, click **Run suite**:

1. Choose the **Agent version** to test — a published version or the **Current draft**.
2. Optionally enter a **Run name**.
3. Confirm. If any test case isn't ready (for example, it has no scorecard that contributes to the result), the dialog lists what to fix first.

The run is queued and executes in the background, so you can navigate away and come back.

## Step 4: Read the results

Go to **AI Agent Testing > Test Runs**. The list shows **Run**, **Suite**, **Agent version** (a version number or "Current draft"), **Status**, **Results**, **Created**, and **Duration**. Search by run or suite name, or filter by status — **All statuses**, **Pending**, **Running**, **Completed**, **Failed**, **Cancelled**.

Click a run to open its detail page. The header shows the suite, agent, target version, creation time, and duration. Below, each test case's result shows its status. Click a result to see the full simulated transcript, tool-call logs, and the scorecard breakdown — each scorecard's score, its pass threshold, and every criterion's result.

<Tip>
When a result fails, read the transcript before the scorecard breakdown — it's usually obvious within a few turns whether the agent went wrong or the scenario itself was unrealistic (a persona instruction that no real caller would say). Fix whichever one is actually broken rather than loosening the scorecard to make the run pass.
</Tip>

Click **Re-run** on the run detail page to run the same suite and version again. To test a fix in your draft, start a new run from the suite with **Run suite** and pick **Current draft**.
